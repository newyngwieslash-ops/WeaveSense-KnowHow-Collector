# 画布交接同步修复设计

## Context

问题与真实失败证据见 proposal.md 和本轮UI证据账。后端HandoffToCanvas由REST与Agent共享，按画布用户归属与revision条件追加节点；前端交接后跳转，画布生命周期调用 `loadCanvasProjectForEditing`，后续自动保存通过 `buildCanvasOperations` 提交局部操作。

加载入口调用方包括画布生命周期、列表导出/预载、画布卡片/文件夹、创作画布续聊、生成任务同步/消费。另有 `syncRemoteUserData` 登录恢复和 `refreshCanvasAfterAgent`；后者已经使用 `mergeAgentCanvasEditor` 保留不冲突的本地修改，不能新建第二套合并协议。

## Goals / Non-Goals

目标：当云端追加交接节点时，已有画布加载和随后的本地保存均保留该节点；本地独立编辑不丢失，同字段冲突不被静默覆盖。

非目标：修改模型执行/审批、同步协议、公开接口、数据库结构、历史规格路由、未配置的真实外部依赖或他人画布Agent修改。

## Decisions

1. **先定位再修复。** 最小失败检查同时覆盖“可信旧基线+本地单字段编辑+新云端节点”的加载返回、store状态和后续发送operations。检查当前候选dirty分支是否产生意外remove_node；必要时补登录恢复对照，不把纯diff函数按定义产生删除视为根因证明。
2. **在共享加载/基线入口处理。** 经失败检查确认后复用已有三方合并及冲突拒绝机制；已确认远端基线与带本地真实修改的投影分开保存。不能仅按intelNodeId重拉、无条件清缓存、直接覆盖local或只在投送模态框刷新，这些会遗漏其他调用方或丢本地修改。
3. **只重放可证明的本地差异。** 不将新remote整份内容直接与旧local做“本地编辑”差分。缺少可信旧基线、同字段冲突或加载期间本地变化时，沿用现有错误/保留草稿语义；不能让后续自动同步把云端新增当成显式删除。实际实现位置由最小检查决定，若需跨模块协调则返回范围选择。
4. **沿用hotfix默认直接执行。** `build_mode=direct`、`tdd_mode=direct`、`review_mode=off`是本新变更预设；仍必须先运行失败检查，再修复转绿并人工核对差异，不启动子代理。用户已选branch隔离，不能改成current。

## Risks / Trade-offs

- 三方合并误把用户真实删除当作保留 → 覆盖显式本地删除、云端独有节点和同字段冲突反例，保留既有按字段操作合同。
- 加载/持久化/回填时序变化 → 检查onLoad、store、已确认基线和后续operations，不只断言页面节点数量；沿用session epoch与本地变化检查。
- 历史脏缓存缺少可信基线 → 失败时保留本地草稿/明确冲突，不自动提交未知删除；不为历史数据增加猜测性兼容层。
- 当前真实失败可能存在不同根因 → RED检查不成立就记录反证，继续追踪，不强行实现上述候选修复。

## Migration Plan

无数据迁移。验证只在已获准的18088隔离环境重建/重验，保持8088和现有卷不变。保留失败画布与新画布对照，不执行真实模型、外发或生产迁移。回退仅涉及本变更源码提交，不回滚其他工作区修改。
