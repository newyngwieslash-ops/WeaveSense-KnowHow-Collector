# 画布待同步编辑与回执衔接

## 能力边界

登录后的画布编辑通过现有用户scope存储保留，通过共享用户数据同步服务调用operations API保存。用户把正则或其他合法节点字段改好后，在正常可写、可信基线成立且无冲突时，自动保存与显式保存必须能提交最新编辑；本地成功不能冒称云端持久化成功。该能力覆盖编辑、加载、调度、持久化日志、提交、回执与后续编辑衔接，不定义数据流正则求值语义。

## 正常编辑与确认

编辑器更新保留在当前账号scope，本地与云端基线应分别表示实际编辑与已确认事实。保存依据真实可信基线生成局部operations，不整份覆盖云端。正常提交成功且服务端版本有效、必要远端读取确认完成后，才能更新已确认基线和“已同步”状态。

网络请求、日志落盘或远端确认期间的新编辑必须保留；旧提交完成后继续提交剩余差异，旧回执不能覆盖较新的合法值。无关节点、连线、云端新增对象及本地视图不能因旧投影反向删除或成为无关覆盖。

## 未确认操作和重开

已发出的未确认mutation必须保持原ID及有效payload，在重试或重开时按原协议重放或确认同一请求，再提交其后的新编辑。不能因ACK未知重新生成业务操作、用新payload复用已有成功ID或把当前云端值冒充旧前置条件。确认后的日志清理沿用正常日志生命周期，不把手工删除日志当故障修复。

可靠旧基线可由既有可验证状态恢复时复用现有能力；无可靠证据时保留编辑并拒绝猜测。原请求、后续编辑和远端最新投影须分别核对，不能用保存旧请求的成功宣告全部编辑已保存。

## 失败处理

暂时网络失败保留编辑和原请求，按现有有界退避调度；永久校验/权限失败、同字段冲突、缺少可信基线必须真实失败，不伪装成功或无限重试。账号切换使旧请求与结果失去应用资格，原scope缓存仍保留，新scope不能承接旧编辑。继续沿用服务端权限、RLS和幂等合同。

## 数据保护

原F03场景及全部旧画布和实采数据保留。验证优先新专项图，原图只有可信基线证明充分时才通过正常应用路径保存。禁止SQL/HTTP强写“修验收”、清缓存、强制覆盖恢复、生产迁移或模型调用。仅保卷更新18088所需web，不动8088；旧dirty及镜像候选来源如实记录，无新依赖、API或表结构变化。

## 验证与收口

先确认本轮完整Shape，再以最小共享状态流检查记录具体RED，确认根因后做共享最小修复并GREEN；反证成立则记录，不为猜测修改。专项覆盖正常编辑、提交中新编辑、未知回执与重开、冲突/基线不足和会话隔离；正式构建与lint按候选执行。真实浏览器编辑/离页/重开与PG落库分别留证，不以单测或静态截图替代。没有独立Verifier时明确限制并取得本次结果接受，归档/提交/交付分别遵当轮授权。
