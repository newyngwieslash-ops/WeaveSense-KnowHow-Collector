# 用户会话与缓存隔离

## 目标与边界

本能力定义登录态工作区在同源多标签页中的身份确认、内存可见性、本地持久化归属和情报目录缓存行为。沿用现有后端session/Cookie认证和权限边界，不建立第二套认证或在标签页之间传递凭据。

## 身份权威与通知

服务端session响应是用户身份唯一权威；标签间通知、共享localStorage键及页面内存只表示需要重新确认，不能直接授予身份或权限。成功密码/验证码登录、注册、退出及外部登录返回后恢复均须进入统一失效/确认边界；相关通知不含Cookie、密钥、私人会话正文。

其他标签获知身份变化后必须先使旧工作区不可见、不可交互，停止旧会话后续业务请求、同步及消费者，再重新读取未被旧缓存复用的session。焦点恢复/可见性变化应能核对遗漏的身份变化；不以无限轮询替代事件和既有恢复入口。无关storage事件不应触发账号切换。

重新确认成功后使用现有applyUserSession完成内存、Query、资源引用和持久存储scope切换；重新开放之前不能保留原用户目录、消息、活动会话、工作区选择或待审批等页面状态。新用户只读取自己的数据；退出为匿名，不显示任一已登录用户缓存。

## 失效与异步顺序

每次身份失效必须使旧认证结果和受保护目录结果失去应用资格。已发起的旧session读取不得覆盖新session缓存、清掉新请求的跟踪或恢复旧用户；目录响应不得因同一userId重新出现而跨越中间一次退出/切换重新生效。

共享目录入口在发起请求时绑定用户及会话代次。返回时资格不符则拒绝应用/缓存，页面调用方正确处理失效或取消结果，不把它当新账号目录；初始加载、创建后的刷新与消息删除后的刷新使用同一规则。显式userId不能成为冒用其他账号缓存的通道。

## 本地持久化归属

各标签的已确认身份决定本地存储scope；其他标签更新共享scope键不能立即改变该页正在排队的存储写入归属。切换中的旧写入完成到原scope，原有本地编辑、持久缓存和待同步journal保留；重新进入原账号可恢复其本地数据。禁止把旧账号数据迁移到新scope，禁止因清内存而把空快照写回覆盖用户数据。

身份失效后旧会话不再自动上传；本地保存不等同云端持久化成功，无法确认归属的保存不得伪报成功。已经在网络上传输的旧操作不能承诺撤回，其返回也不得再改变新账号状态。

## 不可达与恢复

已获知身份变化而无法重新确认时，保持安全阻断，展示原因与重试入口；不能为了离线体验继续显示旧身份私有内容。原账号本地缓存和编辑仍保留。网络恢复后确认最新身份，避免迟到响应恢复较早会话。

同一已确认且未失效的用户可继续使用其自身会话目录warm-start缓存；目录读取失败不删除缓存，不回退到其他用户key。匿名无已登录目录warm-start。正常启动、登录/退出失败反馈和重试必须可用，不形成强制刷新循环。

## 验证与不变量

验收例及其正式ID由brief生成，覆盖双向多标签切换/退出、认证重确认失败、目录和认证迟到响应、共享scope变化下原账号编辑保留、同账号缓存回退及18088真实重验。先最小失败检查，再共享入口修复，保留原专项和相关回归。

不删除localStorage/IndexedDB用户缓存，不清未知脏画布，不改后端API、数据库、RLS或权限；不调用模型、外发、启动子代理、推送、Git合并或发布。真浏览器断网/冷启动、全IndexedDB路径与完整PRD不属于本次通过声明，实际未运行的范围必须单列。数据卷、原画布及实采报告文档保持。
