# Outcome

修复同源多标签页账号切换后旧页身份未失效，以及情报会话目录响应被写入错误账号缓存的问题。旧页在获知身份变化后先停止展示/操作原账号工作区，重新确认服务端会话，再进入正确账号；身份无法确认时安全阻断并允许重试。不以清除持久缓存、刷新页面或模型调用掩盖失败。

# Scope

- 共享认证恢复、认证缓存失效及跨标签通知；覆盖密码/验证码登录、注册、退出与第三方登录返回后的会话恢复，逐个追踪调用方，优先复用原入口。
- 用户scope绑定：标签页已确认身份决定其本地存储归属，另一标签页写共享scope键不能让旧页把原账号数据写进新账号分区。旧账号本地编辑及待同步记录保留。
- 会话目录共享API及三个页面调用点：请求发起时绑定身份/会话代次，身份失效后的响应不得更新当前目录或任一账号缓存。目录、消息与工作区页面状态在身份变化后不得残留或被迟到响应重新填回。
- 用户数据同步、生成消费者和Query缓存的账号切换边界仅作必要复用/修正，停止旧账号的后续同步，不展开重做同步系统。
- 先最小失败测试，再最小修复、相关回归和前端构建；使用18088既有测试账号、保留原数据与卷做浏览器重验。
- 已读调查证据：`docs/flow/2026-10-22-cross-tab-cache-acceptance.md`，只作失败复现和实现参考，不把历史U/A全量范围纳入本变更。

# Non-goals

不更改后端身份、API、表结构、RLS、权限角色或业务账务；不重构无关认证UI、模型协议和同步算法；不恢复/清除未知脏画布缓存；不承诺浏览器真正离线冷启动或完整PRD通过。不新增依赖，不调用真实模型、不外发、不启动子代理/新聊天、不推送、不合并、不发布。

# Acceptance examples

- 同源A/B标签均为账号甲，B成功退出并登录乙后，A收到身份变化即停止展示甲工作区及操作；重新确认服务端会话后只显示乙目录/消息。反向切换、只退出及多次快速切换结果同样正确，不要求用户手动刷新或清缓存。
- 已知身份变化但session接口失败/不可达时，旧页不继续展示旧身份敏感数据、不以旧身份发起后续业务请求或后台同步；显示可理解的重试状态，恢复后确认最新身份再开放。初次匿名/登录流程不被阻断成死循环。
- 目录请求发起后账号发生变化，无论旧响应比新响应早或晚到达，均不得更新新账号页面或错误账号缓存；匿名不读写已登录账号目录缓存，三个现有调用点都遵守共享入口。认证请求缓存失效后，旧在途session结果也不能重新占用最新缓存或恢复旧身份。
- 另一个标签改变共享scope键时，旧标签尚未切换完成的本地写入仍绑定原账号；甲乙已有缓存内容及待同步编辑不被删除或迁移。切换失败不丢失原账号本地编辑，不向新账号上传旧账号内容。
- 同一已确认账号的目录在线读取和接口不可达时的缓存回退继续工作；账号甲不会读到乙标记，账号乙不会读到甲标记。可失效旧身份内存引用和请求，不能调用localStorage.clear、IndexedDB删除或清除用户持久缓存来过关。
- 无模型专项先实际RED再GREEN；相关缓存/同步回归、TypeScript/Vite构建通过。18088两真实标签复验跨标签双向切换、退出、旧目录不残留及接口不可达回退；平台恢复healthy，原画布/实采文档报告内容保持，模型任务及预算无新增。真正浏览器断网等未运行项如实记待验，不冒充通过。

# Constraints and invariants

- 现有HTTP入口、取消和错误传播保持；跨标签消息仅为失效信号，服务端session才是身份依据，不传播凭据、Cookie或私有正文。
- 身份变化时允许隔离/失效旧身份内存和取消旧请求；“不清缓存”指保留用户持久缓存、编辑和同步日志，禁止清库或批量删除掩盖问题。
- 复用applyUserSession及现有持久化/同步暂停能力；切换时先保留原scope的本地写入，再开放新scope。不得等长网络操作结束才阻断旧身份UI/后续请求；已送达服务器的操作不伪称可以撤销。
- 权限、RLS、幂等、预算和SSE合同不退化；不新建服务或无限轮询。不新建索引，使用已有CodeGraph只读定位。
- 文档中文、时间Asia/Shanghai。保留全部既有dirty/未跟踪文件，尤其Agent面板、pending文档、历史归档与本地参考；不reset/clean/restore、git add .。

# Decisions

- 用户选择current模式：继续当前目录和`codex/fix-workspace-member-controls-and-analyst-permissions`，不新建分支/worktree。
- 使用项目已配置的Comet Native，单一聚焦变更；两个问题共享认证/身份边界，不拆子变更。
- 原因已静态核对：AuthSessionHydrator仅挂载恢复；listConversations响应完成后按旧store选择缓存key；getActiveUserScope每次直接读取共享localStorage，另一个标签会改变旧页后续存储归属。后者为必要依赖，先最小RED再修，不以静态推断冒充复现。
- 主会话先RED后GREEN，不启动用户禁止的独立Verifier/子代理。到Verify阶段依Runtime的Verifier不可用流程记录限制，不伪称独立验证通过；最终验收/归档仍按Native实际确认点执行。

# Verification expectations

实施顺序：

1. 对认证通知/重新确认、失效在途session/目录响应、共享scope变更各补最小可运行失败检查，观察实际RED；追踪全部相关调用方。
2. 在共享认证和用户scope入口修一次，复用现有账号切换/本地持久化/同步停止能力；请求按发起身份和代次检查返回归属。保留已有Map缓存测试并补异步竞态，禁止只改标题或清数据。
3. 运行专项及相邻缓存/同步回归，交由Runtime执行最终可重复检查计划，包含前端TypeScript/Vite构建及UI约束lint；不跑无关全仓测试。记录开发检查与正式Runtime检查差异。
4. 18088仅在实际修改需要时保卷更新前端，既有账号两标签重验，不碰localhost原用户画布；接口不可达检查必须恢复服务并核对数据/模型任务预算。持续更新功能/接口说明、pending及证据，未运行项目单列。
