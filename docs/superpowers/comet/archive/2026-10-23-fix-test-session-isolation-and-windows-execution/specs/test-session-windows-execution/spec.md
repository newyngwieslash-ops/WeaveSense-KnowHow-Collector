# 测试会话隔离与跨平台执行合同

## 能力边界

此规格约束仓库测试的执行与结果可信性，不改变产品认证、租户权限、API或持久化行为。Bun组合运行与独立运行应在相同前置条件下执行相同业务断言；测试之间不能遗留会话状态影响。测试环境故障和业务拒绝必须可区分。

## 会话准备与清理

模拟用户须经现有scope/会话入口建立身份，不能只改共享localStorage冒充本标签已确认用户。每个测试自行准备所需window、storage和身份，退出时恢复全局属性、store、auth缓存、scope与其依赖环境，结束或取消本次创建的请求、监听与定时器。复用生产公开入口完成测试生命周期，不在生产文件增加测试bypass或reset后门。

会话专项之后正常受保护请求不因残留身份/revision被拒绝；会话专项中真正的失效、scope漂移、撤销、在途取消、迟到响应和跨账号缓存保护仍拒绝，相关负向断言保持。同账号/跨账号appearance默认值隔离经正式scope入口验证。组合测试通过不能通过把整个测试集改成每文件独立进程获得。

## 文件路径、换行与真实入口

文件URL使用标准库转成本机路径，Windows驱动器、空格与中文路径不丢失；允许名单比较对路径分隔符规范化，仍只豁免既有明确文件。Linux/POSIX语义保持，未实际运行的系统只记未执行，不伪称通过。

临时测试模块必须解析全部当前依赖，并执行真实SSE、请求和会话守卫；仅替换原有网络/UI/存储副作用，不能恒成功绕过身份。LF和CRLF不改变源码导入剥离或入口执行的业务结果；仍失败的语法或未知依赖直接报告，不能吞掉异常。

## Shell与CI fixture

测试使用存在且可执行的本地Bash；Windows可选择已安装Git Bash，不将WSL启动器失败当业务拒绝。临时路径、PATH及换行须适配所选执行环境。fixture只允许mock docker/gh响应，所有成功与拒绝分支均需证明mock实际命中；真实程序不得作为fallback。依赖缺失、启动失败、错误mock解析须形成清晰测试失败，不跳过用例或更改预期掩盖问题，不下载安装软件。

## 结果与保护

先新增最小失败检查并实际观测RED再修对应边界，保留全部既有业务断言。专项组合、必要构建/lint验证后，真实执行全Web并记录原始结果及逐项去向；范围外旧债不视作通过，也不能降低断言要求。源代码业务行为不变；产品问题、数据恢复、真实模型、外发、部署或Git交付须保持独立范围与授权。
