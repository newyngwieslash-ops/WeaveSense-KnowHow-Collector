# 画布JSONL数据源文件导入

## 能力范围

现有画布数据源文件选择器支持.jsonl扩展；其内容经共享数据源求值器按JSON Lines读取，仍使用现有format=json与fileName元数据，不引入新存储类型或API。适用于新导入、编辑后重新求值、保存/重开及原生画布导入中保留该元数据的节点。

## 格式识别与隔离

仅当实际数据源格式为json且文件名trim后不区分大小写以.jsonl结尾时应用逐行规则。无此文件标识的JSON保持整份JSON.parse语义；合法普通JSON数组或包装对象继续使用原行为，非法普通JSON不因类似逐行记录而宽松接受。用户明确改为CSV/TXT/Markdown/intel时尊重当前格式，即使文件名仍为.jsonl。

本能力只影响共享parseDataSourceNode边界，不扩大通用parseJsonItems的合同，不改变普通文本、情报或TXT调用方的试探解析与降级规则。

## 逐行读取与标准化

读取原始正文中的LF/CRLF物理行；首尾空白、纯空白行及文件起始UTF-8 BOM不产生记录，空白文件得到空集合。非空行必须各自是一个标准JSON值，按原行顺序输出一条CanvasDataItem。

标准化复用既有toCanvasDataItem：对象保留字段，字符串/数字/布尔值保留类型，null沿用空字符串表示，行内数组沿用已有数组包装对象。一行是一个记录，不把该行对象中的items/rows/data/records/list或行内数组展开成其他行。字符串内转义换行按JSON解析，不把格式化多行对象当成多个合法JSONL记录。

## 错误与下游

任一非空物理行非法时返回0条及明确中文JSONL解析错误，指出原物理行号；忽略空行不改变编号。已经解析的前面行不返回部分集合，不跳过坏行、不回退TXT、不修复内容。文件正文和名称保留供用户修正，不清用户缓存。JSON解析不执行文件中的命令或脚本。

合法记录进入现有数据流求值、条目计数、字段预览及下游算子；错误时不把部分记录作为成功输入。保存/reload遵循现有云同步及scope边界，不改RLS或持久协议。
