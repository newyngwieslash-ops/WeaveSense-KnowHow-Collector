# 画布TSV数据源文件导入

## 能力范围

数据源现有文件入口接受.tsv，以format=csv、fileName和rawText持久保存；在共享parseDataSourceNode边界选择制表符拆列，供预览、字段列表、全部下游数据流及保存重开复用。无需新枚举、页签、迁移、API、表结构或依赖。

## 格式选择

实际格式为csv且fileName去首尾空白后不区分大小写以.tsv结尾，才按制表符解析。普通.csv、缺少文件名的CSV和parseCsvItems不指定分隔符时仍使用逗号；不从正文猜测分隔符。用户明确改选JSON、TXT、Markdown或intel时，残留.tsv文件名不覆盖实际选择。JSONL的既有json/.jsonl规则独立保持。

## 拆列与转换

多行文件首个非空物理行为表头，后续每非空物理行对应一条记录，支持LF/CRLF与中文。首尾制表符代表真实空列，不能在拆分前用trim吞掉；起始UTF-8 BOM不成为字段名或记录。纯空白行不产出，空文件得到0条。

表头和单元格沿用现有CSV行为：空表头col_N、按表头映射字段、缺失/空值为空字符串、trim及数字/布尔转换不改变。只有一个非空物理行时，继续返回现有非空单元格列表；不新增独立表头模式、重复表头或行宽校验。

复用既有引号扫描器并传递制表符分隔参数：引号内tab保留为单元格数据，双引号转义按原规则处理，逗号不会变成TSV分隔符。沿用既有宽松解析与标量规则，不扩展跨物理行引号字段、严格语法报错或自动纠错。

## 下游与持久化

两条id/title/score中文数据应得到两个三字段对象，title可被既有提取算子读取，score沿现有规则为数值。原始正文/文件名保持，保存刷新通过同一共享解析入口重新求值，不清缓存、不覆盖其他用户编辑。

brief的六项验收覆盖标准数据、空列与换行、引号规则、格式隔离、正式RED→GREEN及构建、18088真实闭环。本规格不重复生成Scenario项。不改连线/重连、CSV/JSONL或其他U/A能力；不调用模型、不清缓存、不启动子代理、不推送/合并/发布。无独立Verifier时如实记录，本轮结果接受及本地归档单独确认。
