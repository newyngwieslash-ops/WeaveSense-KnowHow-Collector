# 视频行业知识扩展架构

## 权威划分

| 组件 | 负责 | 不负责 |
|---|---|---|
| 现有 Go 平台 | 当前用户/工作区、角色授权、MCP 服务与 schema 审批、Agent/Canvas、模型任务和财务账本、原生 Skill 编译/部署/安装收据 | 不另存一份视频任务业务状态，不接受客户端伪造 tenant/grant |
| Loom 主 Flow Engine | 来源与授权、不可变 profile、发现游标、视频任务/阶段/租约、两阶段 manifest、文档修订/证据、审核知识、方法候选、删除权威投影 | 不使用 legacy collector，不独立建立登录/计费/并行调度 |
| Python video worker | DTK 协议适配、受限媒体获取/解码、ASR/OCR/视觉执行、不可变产物、执行意图/恢复和物理清理收据 | SQLite 仅保存执行事实，不决定知识审核、发布或业务 ready |
| 独立删除日志 | 认证、只追加的撤权/删除意图及高水位，防止旧数据库/对象备份复活已禁用内容 | 不保存原文，不随业务备份回退，不由媒体 worker 修改 |
| 现有宿主 Web | 领域、来源、任务、证据、知识审核、方法版本与指标的统一入口 | 不新建平行知识笔记站或登录界面 |

所有新增状态沿用既有租户/工作区隔离。固定的内部服务传输例外与具体 IP/身份/audience 绑定，不放宽公共 HTTP 工具的出站策略。服务 token 不是用户权限；短时签名委派携带 scope、任务、attempt 和 fence，仍需当前授权。

## 数据与状态链

1. 用户批准的来源和不可变 profile 版本进入已有主 Flow 调度。发现页独立持久化，分页未结束不提前提交稳定游标；历史资产复查由同一调度推进。
2. 规范化平台/native/part 身份和业务幂等键决定资产及任务。JWT 的临时 jti/iat/exp 不参与业务指纹。一个资产可关联多个来源，不把转载/近似内容自动视为独立权威。
3. 外部提交先记录意图，失去响应时按 scope+幂等键/外部 task ID 对账。未知执行结果保留预算与资源占用，不把“未返回”当作“未执行”，取消请求也不等于远端已停止。
4. `input_ready` 验证输入对象、字节数和 hash；`processing_complete` 绑定输入 parent hash、处理器身份、分片、时序与覆盖。长文本分片和视觉分页不以截断冒充完整。
5. 媒体、ASR 文本、OCR、视觉观察和摘要保留材料类型。机器观察不能伪装成原始引文；有坐标/时间戳也不等于结论正确。音频/画面不一致作为待审核候选而不是静默覆盖。
6. 所需阶段和可选缺口明确区分。文档修订、索引/向量和 ready/outbox 在权威事务边界内切换；旧修订与证据引用仍固定其原始媒体 hash。修订人工转写不重写旧引文。
7. ready 后进入独立知识提炼队列，生成候选而不是自动发布。审核绑定版本、内容 hash 和证据快照；已发布检索不退回未经审核的原始资料。
8. 方法候选冻结 base、知识 release IDs、证据及规则映射，三基线行为评估与人工批准后才可导出。源码构建、实际宿主 attestation、CAS 工作区安装是不同关口。旧运行固定其方法与知识快照，但当前撤权仍能阻断旧快照读取。

## 执行与成本

父任务预算和子模型/ASR/OCR准入通过现有 Go 账本，不能用 worker 自报费用替代结算。Loom 只保存相关收据和累计使用事实。资源配额对字节/媒体时长预留，未知结果不自动释放；磁盘水位和临时空间限额在大文件写入前/期间检查。

并发由既有租约与 fence 维护，支持工作区/来源/供应商约束，不通过新增独立 scheduler 绕过。输入不变且处理身份相同才允许精确缓存复用；模型/profile 或媒体变化进入新处理。缺失对象修复必须显式授权和预算，不允许 GET 播放链接偷偷触发下载。

指标从既有权威记录派生，不新设业务数据库。任务成功、音频处理时间覆盖、视觉采样密度、知识审核状态和人工质量是独立维度。费用未结算显示未知而不是零；有成本的样本按 profile/model/media 版本归因，采样窗口和截断上限必须可见。

## 删除与恢复

正常媒体到期可以保留仍获授权的文字知识；原始材料最大期限、授权撤销和硬删除不能仅清理某个对象而留下可读的派生缓存。保留策略冻结在 profile/job，引用、活动租约与后续修订按实际关联核验。

权威日志意图先持久化，再进行数据库事务；旧备份恢复时先恢复对象和数据库，再重放最新独立日志。Loom 文档/索引/知识/方法、worker 执行存储与 Go 对话/原生 Agent 缓存各自回执，任何缺失不能汇总成“已全部擦除”。DTK 的 cancel API 不是供应商物理删除证明，外部数据/模型缓存的保留边界单独记录。

## 文件索引与证据

- `flow/video.ts`：主协调器；`video-contract.ts`：对象与 manifest 基础合同；`video-resources.ts`：资源准入。
- `flow/video-knowledge*.ts`：证据/知识/候选、提炼与原生方法；`video-origin-candidates.ts`：可人工判定的近似来源候选。
- `flow/video-journal.ts` 与 `video-retention-policy.ts`：独立删除日志、恢复屏障与分类到期。
- `services/video-knowledge/`：执行 worker、DTK、媒体与测试；宿主原 ASR/OCR worker 保留单独生命周期。
- `backend/internal/flow/video_*.go`：宿主代理、MCP、模型/预算、方法与删除投影；`backend/internal/{app,repository}/video_retention*.go`：原生运行留存。
- `backend/cmd/video-skill-release`：只产出受审源码，不部署。
- `web/src/pages/intelligence/video-*.tsx`：现有控制台界面。
- `validation/video-knowledge/shared-contract-v1.json`：位于 `services/loom-engine/` 下的三语言共用正反例；各语言运行真实所属边界，不重复伪造业务权威。

源代码存在不等于验收完成。原始 107 项任务和各条验收条件完整保留，最终状态以 `PROGRESS.json`、独立测试记录和发布门槛为准。
