# WeaveSense 视频行业知识工作流 实施主提示词

你是本项目的实施负责人，需要在实际代码仓库中完成开发、集成、验证和交付。请阅读随附规格后直接推进实施，持续完成本提示词定义的完整 V1。

## 一、最终目标

在现有 WeaveSense-Math 中实现一条持续收集垂直行业知识的工作流：

用户配置行业知识域、B站和抖音的视频来源及采集频率后，系统能在聊天和浏览器关闭时继续发现新增视频，获取可使用的内容，完成字幕或语音转写及必要的画面理解，将结果转成可追溯、可复核、可检索的知识，供宿主 Agent 使用；经过评测和批准的可复用方法，可以进一步成为有版本的原生行业 Skill。

项目定位是 WeaveSense-Math 的扩展组件。复用宿主的工作区、身份、权限、界面、Loom、Agent、Canvas、模型网关、预算、知识存储和审批能力。不要另建独立 SaaS、独立登录计费系统、另一套笔记前端、平行知识库或自治调度平台。

本次完整 V1 包含 P0 与 P1。完成标准是实际宿主中的完整业务闭环、故障恢复和验收证据，不能以生成设计文档、工具壳、独立 demo 或单个 SKILL.md 文件替代。

## 五、架构边界

1. WeaveSense-Math 负责工作区身份、Agent、产品界面、审批、预算与模型入口。
2. Loom 是来源、调度、游标、video job、文档修订、证据、知识状态及发布事件的业务权威。
3. DTK 作为内部 Provider，负责经过验证的平台发现、元信息和下载能力。其任务与存储只属于执行层，不作为业务知识权威。
4. 视频处理组件复用 BiliNote 中适合抽离的逻辑，例如抽帧、网格和提示组织；明确记录复用内容与改造。不要直接搬入其前端、单视频 Chroma、聊天系统和调度器。
5. 优先复用宿主 ASR、OCR、Model Gateway、现有全文检索和可选向量能力。所有模型调用进入宿主预算和 usage 链路。
6. 手工、定时、API 和 MCP 必须汇入同一个 Loom 协调器与任务存储。MCP 是受控入口，不能建立另一套任务事实。
7. Go 平台与 Loom 按现有内部 API、Outbox/Inbox 通信；处理服务不能越过 Loom 直接写业务表，也不能自行伪造宿主 evidence_id。
8. 同一来源只由 Loom 调度。不要同时启用 DTK watchlist、BiliNote 定时器或新的独立 cron。

M0 必须核对实际执行路径，重点包括：

- `services/loom-engine/flow/engine.ts`、来源校验、connectors 和相关 migrations。
- `backend/internal/flow/mcp.go` 与 `backend/internal/flow/egress.go`。
- `services/loom-engine/flow/enrichment.ts` 及 ASR/OCR worker。
- `backend/internal/flow/skills.go`、原生 skillpacks 及普通 Skill 包加载路径。
- Canvas 数据源、monitor、自动运行、文档修订、证据和索引路径。

前期调研中的关键问题需要逐个核实和处理：主 Flow 来源约束尚未接通视频；legacy collector 不能代替主链路；ASR 上层可能丢弃 segments，worker 存在静默截断；Canvas MCP 返回值不会自动导入知识库；原生 Skill 和普通 SKILL.md 属于不同执行机制。

## 六、来源、调度和持久任务

平台原生 ID、作者 ID 以字符串保存；B站分 P 要进入资产身份。归一化分享短链与规范 URL，保持来源订阅和视频资产可多对多关联。

分别保存稳定 watermark、分页 checkpoint 和处理进度。每页发现清单、来源关联、待处理任务、checkpoint 与必要事件在事务中落库。扫描到旧边界或穷尽约定范围后才能推进稳定 watermark；分页失败、限流、页上限、游标失效和乱序必须保留 partial 及恢复点。覆盖置顶、重叠页、分页期间插入新视频和首次有界导入。

复用宿主 interval/cron、时区、misfire、授权、预算和调度锁。支持暂停、恢复、立即运行及有界补采。持续采集必须脱离聊天连接和浏览器存活。

持久化 operation、video job、stage、attempt、输入和配置版本、外部 task 映射、下次轮询时间、重试、lease、heartbeat、fencing 与稳定错误分类。worker 使用原子 claim、持续心跳、租约接管和条件提交；旧 worker 或旧阶段 token 不得提交结果。不能用内存队列、一次 Promise 或 HTTP 后台回调替代持久任务。

按 PRD 实现状态及语义，包括 queued、running、retry_wait、blocked_auth、blocked_budget、reconciliation_required、cancel_requested、cancelled、failed、completed、completed_with_gaps。必需产物缺失不能以 completed_with_gaps 绕过就绪门禁。

幂等键按发现、下载、处理和导入分别设置命名空间；业务指纹包含 workspace、资产身份、内容版本、profile、processor、模态及关键模型配置。相同键同参数复用，相同键异参数冲突；不要把所有阶段复用一个字符串视为完整幂等设计。

调用 DTK 等外部服务前持久化 submission intent。外部接单后响应丢失，使用已确认 ID 或上游确实支持的查询核对；无法判定时进入 reconciliation_required，禁止盲目重新提交。宿主幂等不代表上游具备 exactly-once。pending 轮询不能再次发起下载。

**特别处理“start 响应丢失，调用方连 video_job_id 都没有”的情况：**提供基于可信 scope 和宿主幂等键找回 operation/job 的内部恢复映射或等价适配，与 Gateway 的 reconcile 语义一致。不能要求所有恢复请求都先提供未知的 job_id。此项属于 IF-003、IF-007、COL-013、COL-019 的契约补全。

取消先持久化宿主取消、阻止继续处理和发布、使旧 fencing 失效，再尝试取消远端任务。远端结果分别记 requested、confirmed、unsupported、unknown。晚到产物隔离与清理，不能恢复成成功；已发生 usage 保留。

后台按授权失效、限流、临时故障、永久不可用、契约变化、预算不足、存储失败和外部结果不明分类处理。尊重 Retry-After，设置退避、抖动、上限与可解释恢复操作。预算和资源限制必须在后端生效。

## 七、内容处理、产物与知识就绪

优先使用真实取得且质量可用的时间轴字幕，缺失或质量不足时调用宿主 ASR。保留原始字幕、ASR segments、语言、时间区间和处理版本。平台是否提供独立字幕或纯音轨需要实测；音频模式不能承诺一定减少首次下载流量。

长音频按受控片段处理，保存覆盖清单、分段状态和 hash，支持中断恢复与重叠去重。消除静默截断，不能只提高原有字符或 segment 常量。区分全视频覆盖、有效语音覆盖、静音、未知区间、可选缺口与必需缺口；不伪造说话人或精确时间戳。

媒体先流式写入临时对象，检查大小、类型和实际 hash 后提交。半文件不算成功，临时签名 URL 不作永久证据。对象进入宿主受控存储，读取和回收均验证 scope。

产物采用两阶段契约：

- `artifact_stage=input_ready`，`input_kind=platform_subtitles|media`。只有字幕时 `media_sha256=null`、`availability=not_acquired`，`input_hash` 对应真实输入，界面不能承诺本地视频播放。
- `artifact_stage=processing_complete`，使用 `parent_manifest_sha256` 绑定已接受输入，提供分段对象、hash、时间范围、覆盖情况、processor 与配置版本。

两个阶段绑定同一 video job，但使用各自 stage attempt 和 fencing token。处理阶段不得复用已经过期的下载租约。

**K-017 是唯一知识就绪协调器：**检查受信导入、scope、产物 schema/hash、必需覆盖、文档修订、UTF-16 映射及索引可用，然后原子切换可见版本并写入 video.knowledge_ready outbox。K-018 的分块与索引在该屏障之前完成。全文索引属于默认就绪条件，可选 embedding 状态独立表示。

collection.completed、DTK done 和 worker success 都不等于 knowledge_ready。新修订失败时旧 ready 修订继续可读。事件重投只能产生一次有效的下游整理运行。知识整理是 ready 后独立 Flow 运行，不作为媒体任务自身必须等待的阶段。

视频 monitor 在 ready 后按实际内容重新评估命中，进行有界聚合与 revision 去重；避免每个回调触发重复全量研判。

P1 视觉处理需覆盖场景抽帧、时间网格补充、OCR、必要的 VLM、帧时间与原件引用。每个任务使用独立临时目录；短视频、尾组不足网格和取消并发任务不能丢帧或污染其他任务。视觉必需模式失败时阻止完整 ready；可选视觉失败才允许明确降级。

## 八、知识和证据规则

至少区分来源原件、带处理血缘的材料表示、模型派生结论和已发布知识。标题/描述更新不能覆盖转写。ASR/OCR 可作为来源对应的材料表示，LLM 摘要和推断不能循环充当自身的原始依据。

在宿主现有 document、revision 和 evidence 模型上扩展时间与帧信息。证据必须固定不可变 revision，文本坐标遵循 `${title}\n\n${body}` 的 UTF-16 偏移，不是字节数、Unicode 码点数或转写子串局部坐标。覆盖中文、emoji、跨段引用、人工修订与历史版本。没有可靠时间轴时明确 unknown；人工改写造成对齐失效时按段级降级并记录 alignment_method。

知识卡至少包含类型、领域、结论或问题、步骤或参数及单位、适用对象和条件、边界与反例、证据、事实/观察/推断类型、有效时间、冲突关系和审核版本。材料没有提供的信息返回缺失，不得补造数字、单位、条件或结论。

知识状态按 candidate、in_review、approved、published、rejected、withdrawn、superseded 管理。修改后旧批准失效；审核与发布使用预期版本/hash 和权限检查，阻止旧批准发布新内容。

区分两类读取：研究与整理角色可按权限访问 ready 原始材料，明确未审核或来源主张；普通行业知识工具默认只返回有效 published 知识，不能在没有答案时无声回退未审核材料。

转载通过 origin_cluster 等来源关系处理，不因跨平台转载增加独立佐证数。冲突保留来源、时间、适用条件与版本，不能简单多数表决或覆盖另一方。

停用订阅、媒体正常到期、远程下架、撤权和内容擦除分别处理：停用只停止未来采集；正常到期标记 media_expired，仍获授权的文本可保留；远程下架标记 remote_unavailable 并按授权处理；撤权/擦除必须传播到检索、证据、知识、缓存和 Skill 依赖。备份恢复后重放删除墓碑，不能使已撤回内容重新可用。

## 九、MCP 和内部接口

实现 PRD 中拟新增的 MCP 控制工具：

- `video_discover`：有界发现，带 deadline；慢查询返回发现句柄，不隐式下载。
- `video_process_start`：短提交，返回 operation_id、video_job_id 和状态。
- `video_job_status`：阶段、错误、覆盖、能力与下次轮询提示。
- `video_result_read`：分页结果或 manifest，包含 next_cursor、完整性及校验信息。
- `video_job_cancel`：宿主取消状态与远端停止状态。
- `video_job_reconcile`：受限核对，配合无 job_id 时的幂等键恢复路径。

长处理放入后台持久任务。遵守宿主实际调用超时，前期基线约束为 10—30 秒；不能用无限延长全局超时解决长视频。正文分页，大文件使用受控对象引用。MCP TextContent 保持简短，不要与 StructuredContent 重复整份 JSON 导致截断。

tenant、workspace、actor、grant、source scope 必须来自验证后的宿主委托上下文，不能信任模型传入的权限字段。静态连接密钥只代表服务身份，不能代替工作区授权。执行、读取与发布时按当前授权复检。

为同部署内部服务实现固定 allowlist、明确服务身份和 audience 的受信传输路径；保留现有 PublicTransport 对普通外联的隔离。禁止全局 AllowInsecure、允许任意私网目标、关闭 SSRF 校验或随重定向转发凭据。内部 MCP 连接必须在真实 Gateway 路径验证，不能仅证明 curl 可达。

落实任务创建/查询/取消/导入/产物读取、领域 profile 读写及知识 review/publish/withdraw 的受限内部 API。PRD 中路径是设计建议，M0 可按仓库约定调整，但语义、权限、幂等、版本冲突、错误分类和验收不得丢失。

profile 必须在 Loom 中持久化、版本化，并由每次运行冻结引用；不能只放在前端或 industry-packs 导出文件中。改变工具 schema 时遵循宿主批准及 schema hash 机制；安装 Skill 不能隐式批准 MCP 连接或扩大工具权限。

## 十、原生行业 Skill

P0 实现固定的 `video-knowledge-core` 原生整理 Skill，包含相关性判断、证据获取与核验、知识提取、冲突与缺证处理、工具权限和结构化输出。必须在宿主 intelligence 和 Canvas 的真实执行路径中验证加载与调用。

核实并复用宿主原生 JSON skillpack 的构建、内嵌、安装和 pin 机制。普通 SKILL.md 不会自动执行脚本、启动服务或创建后台调度；industry-packs 导出目录也不能直接当作运行时热加载源。

新视频通常更新知识库；只有形成稳定、可重复使用且经过业务评测的方法改变时才创建方法 Skill 候选。不要让每个视频自动修改生产 Skill。

P1 完整链路为：

**候选 → 冻结基础版本、证据和候选 hash → 固定评测 → 行业批准 → 生成源控发布包 → CI 构建 → 部署 → workspace 安装并 pin → 可回滚。**

批准、部署和安装状态分别保存。新部署仍应保留旧 version/hash 可加载；旧运行可追溯，当前权限撤销仍有效。候选评测覆盖正向、负向、不适用、缺材料和回归用例，并在相同模型和输入下比较既有版本及无 Skill 基线。不得以“生成了一段方法说明”替代可执行原生 Skill。

## 十一、宿主界面和运行部署

在现有 UI 中完成领域配置、来源管理、调度、任务列表与详情、知识候选、复核发布、证据侧栏、撤回和 P1 Skill 候选/评测/发布/安装视图。沿用宿主身份、导航和权限。

界面分别显示资料就绪、知识已发布、Skill 已部署和已安装。进度以真实阶段为准，不伪造百分比。展示需要更新凭据、预算阻断、部分覆盖、外部结果不明、媒体到期等可操作状态。

视频引用应能在授权可用的宿主媒体中定位，或显示来源与时间区间。平台不支持精确跳转或媒体未获取/已过期时，不能承诺精确播放。

提供固定版本的开发/测试启动方式、必要服务配置、环境变量示例、迁移、健康检查、资源限制、日志和监控。凭据通过 secret reference 提供，不能进入源码、普通日志、模型上下文或 MCP 返回。

来源记录内容使用依据、允许用途和保留条件；开源软件许可证与视频内容使用权限分别管理。缺少有效访问授权的资源明确阻断，允许使用合法提供的原件，不实现付费、登录权限、DRM 或验证码绕过。宿主到 DTK 的服务密钥与平台 Cookie 分开管理。

保持 RSS、Telegram、WeChat、既有 ASR/OCR、检索和 Canvas 路径兼容。外部 Provider 不可用时应明确降级，不能让整个宿主无法启动。通过 feature flag 和工作区灰度上线；回滚可暂停新任务并保持历史文档和证据可读，不能依靠重建共享数据库恢复。

## 十三、验证与验收要求

用真实实现验证关键风险，避免只测试 mock 返回值或实现自身。需要保留契约测试、数据库/对象存储集成、宿主端到端、必要 UI 验证及故障注入证据。

1. B站和抖音分别完成单链接处理、账号增量和两轮实际调度；关闭聊天后继续运行。
2. 手工、定时及 MCP 入口对同一内容的重放不重复发布，同键异参冲突。
3. worker 被终止、租约过期、旧 worker 恢复、外部接单后断连、事务结果不明和旧 fencing 回传。
4. 分页失败、重复页、乱序、429、授权撤销、预算耗尽及可恢复阻断。

8. UTF-16、emoji、跨段时间引用、元信息更新不覆盖转写、旧引用可解析。
9. 索引失败阻断 ready、旧版本仍可读、outbox 重投不重复触发有效整理。
10. 无依据的事实、旧批准失效、发布撤回、转载与冲突、普通检索不返回未审核知识。
11. 跨工作区 ID/对象篡改、提示注入、SSRF/重定向、凭据泄露和工具 schema 变更。
