1 项目定义与交付目标

项目名称为 WeaveSense 视频行业知识工作流。它是 WeaveSense-Math 的扩展组件，持续接收指定平台与账号的新视频，形成可定位原始内容、可复核、可检索的行业知识，并把经过验证的方法沉淀为有版本的行业 Skill。主系统继续承担工作区、身份、调度、预算、Agent、知识检索与产品界面。[S01]

完整首版的交付结果是：来源维护人配置一个领域、两个平台的来源和采集频率后，聊天关闭时后台仍持续执行。行业人员能在宿主内查看候选知识、打开视频时间段核验、发布有效知识。宿主 Agent 随后能够引用这些知识完成行业任务。经过评测与批准的方法可以发布为指定版本的 Flow Skill。

[表格]
层次	交付物	验收含义
材料层	视频元信息、受控媒体、字幕或ASR、可选帧证据	内容完整性可见，来源与处理版本可追溯
知识层	带来源和适用条件的知识卡、复核与发布记录	可检索、可撤回、可通过证据核实
方法层	原生整理Skill与经评测的行业方法候选	可在真实宿主路径执行，版本可部署和回滚

成功定义

连续两个以上调度窗口及服务重启后，来源仍能增量采集，且相同内容不会重复发布。

资料就绪、知识已审核、Skill 已部署安装三种状态分别可观察。

最终回答能追溯到具体视频、内容修订和时间区间；没有依据的事实不会通过发布门禁。

完整V1包含P0和P1，P2只作为后续扩展清单。

当前交付与后续实施

本版本 PRD 和配套任务表是实施基线。开发完成需要提交代码、契约及回归测试、可运行部署、真实宿主端到端证据和试点验收记录；写完适配器或生成一个Skill文件不构成交付完成。

2 现有基础与需要补齐的能力

源码基线固定在2026年10月26日核验的提交。宿主已有Loom调度、文档修订、证据、MCP Gateway及行业Skill机制；它们分别有运行边界，新增工作应进入现行flow路径。[S01-S08]

当前Engine.createSource与数据库约束只接受rss、telegram和wechat。另一套历史collector中的bilibili入口不能代替本次现行链路接入。[S02][S10]

宿主ASR worker已返回segments，但上层处理未完整保留时间轴；worker现有输出还存在text[:400000]和segments[:2000]截断。需要完整性协议和分段产物，不能仅提高一个长度常量。[S04][S05]

现有Canvas的mcp_tool数据源可消费工具结果，结果不会自动变成文档、revision与evidence。导入与证据创建仍由Loom受信逻辑负责。[S07]

Flow原生行业Skill由Go内嵌JSON加载；普通SKILL.md包有另一套安装与读取路径。首版采用前者执行行业整理与方法发布，并可在后续提供交互辅助的文件包。[S06][S11][S12]

本项目支持保存完整视频，也允许字幕优先和只获取必要音频。任务配置明确所需模态和保留策略；对画面依赖型任务，字幕完成不等于任务完成。平台访问失败以可观察状态呈现，不通过规避访问控制来承诺下载成功。

上述是产品处理策略，不表示所有平台都提供独立字幕或纯音轨接口。M0冻结Provider能力矩阵；字幕不可用回退ASR，无独立音轨时临时获取视频后提取音频。音频模式控制后续处理和保留，不承诺一定减少初次下载流量。

主要用户旅程

首次配置：在原工作区创建知识域，选择术语与目标问题，添加B站UP主和抖音账号，测试连接，选择处理模态、调度和预算，预览首批发现量，使用宿主既有授权流程启用。

持续运行：Loom按窗口发现新增内容并提交后台任务。用户在任务页看到来源、阶段、进度依据、费用和失败原因，按授权更新凭据或重试失败阶段。

知识使用：行业复核人从候选列表进入证据侧栏，核对时间区间与原文，补充适用条件后发布。Agent按问题检索已发布知识；需要查看原始未审核材料时明确展示其状态。

方法沉淀：多条已审核知识形成稳定做法后，创建Skill候选，使用冻结评测集比较效果，批准后经构建部署，在workspace安装并固定新版本。发布失败继续使用旧版本。

5 总体架构与责任归属

采用宿主控制与入库、平台适配器获取、独立媒体执行组件处理的结构。Loom是持续任务和知识状态的唯一权威。MCP提供调用入口，Flow Skill规定行业整理步骤。

[表格]
模块	职责	数据归属
Go平台与现有MCP Gateway	鉴权 委托scope 连接审批 界面 Agent 审计与预算	flow_platform中现有平台数据
Loom扩展	视频源 发现游标 任务编排 导入 文档证据 知识状态 ready事件	flow_intel及宿主对象存储
Video Knowledge组件	MCP薄接口 处理执行 BiliNote抽取逻辑 产物manifest	只保留可重建缓存与受控中间产物
DTK内部服务	平台查询 下载任务和平台侧会话	DTK自有运维存储，不作业务知识权威
原有ASR OCR及Model Gateway	语音识别 光学识别 语义整理和视觉模型	复用宿主授权 usage及调用追踪

两类入口与同一任务链

定时入口由Loom调度直接进入video job协调器。交互入口由Agent经MCP Gateway调用video_process_start，MCP服务通过受信API进入同一个协调器。各入口共用业务去重指纹；发现、下载、处理和导入分别使用独立命名空间的确定性幂等键，并保存关联关系。

Worker的处理成功只表示产物可获取；Loom核验manifest并导入文档、证据、索引后才决定就绪。所有跨服务写入走API与Outbox/Inbox，不跨库直接写表。[S01]

默认部署选择

完整V1按同环境部署设计。DTK及视频处理进程在内部网络运行，只由宿主既有入口提供界面。MCP连接新增显式受信内部服务传输配置，目标由部署配置固定并绑定服务身份；现有公网MCP仍使用原PublicTransport。禁止给用户或模型一个任意内网URL开关。[S03][S09]

若部署环境已具备独立HTTPS服务域名，也可走现有公网MCP连接能力；它属于同一契约的部署选项，不改变宿主调度与入库责任。

DTK watchlist与BiliNote自带调度不得对同一来源并行启用。平台服务只执行Loom发起或统一协调器接受的查询、下载和处理，防止两套游标与任务同时运行。

6 核心流程与状态模型

发现到知识发布

调度窗口冻结来源与领域版本，每页发现清单与待处理任务原子保存。单视频任务先取得可用字幕或媒体；需要ASR或视觉时再获取相应音视频。Loom校验产物完整性、建立revision和证据映射、完成必要索引后发ready事件。行业整理Skill作为下游Flow运行生成候选知识，复核批准后发布。

稳定watermark仅在扫描到旧边界或穷尽结果时推进；分页失败、风控、页上限保留partial和page checkpoint。媒体处理不阻塞已完整发现窗口的watermark，但所有已发现条目必须有持久任务。补采有固定窗口和上限，失败条目独立恢复。

[表格]
对象	状态或阶段	关键规则
video_job	queued running retry_wait blocked_auth blocked_budget reconciliation_required cancel_requested cancelled failed completed completed_with_gaps	completed止于宿主ready；with_gaps仅容许非必需分支缺口，必需缺口不能ready
处理阶段	discover input acquire transcript vision normalize import index	curate属于ready之后的关联Flow run；每阶段独立attempt lease和fencing
知识卡	candidate in_review approved published rejected withdrawn superseded	编辑使旧批准失效；普通行业检索仅使用有效published知识
Skill候选	draft evaluating review_pending approved_for_release deployed installed rejected retired	批准不代表部署或安装成功

ready事件

新事件video.knowledge_ready由Loom生成。它至少包含event_id、schema_version、scope、operation_id、video_job_id、source_id、profile_version、document_id、revision、available_capabilities、coverage摘要及内容指纹。消费者按事件ID和业务键去重。

只把FTS文本索引作为首版默认就绪门禁；可选embedding异步完成时独立记录索引版本与可用状态。需要视觉的任务必须等必需画面分析完成。知识已发布另以knowledge.published表达，不能复用ready语义。

处理产物先暂存。索引、映射或必需分支失败时，不把半成品暴露给常规材料检索，上一已ready版本仍可用。恢复后原子切换可见revision并写outbox。ready材料允许研究和提炼角色读取，普通行业知识查询不会静默回退这些未审核材料。

外部结果不明与取消

宿主提交下载前持久化intent及关联键。远端接受后响应丢失时，优先使用已确认ID或上游实际支持的查询能力核对；未验证上游幂等能力时进入reconciliation_required，禁止盲目重新提交。宿主幂等不等于外部服务提供exactly once。

取消先撤销宿主继续处理与发布资格，再请求远端停止并记录confirmed、unsupported或unknown。不能把宿主cancelled误报为远端已经停止。晚到产物隔离清理，已经发生的下载与模型usage继续按实记录。

周期工作流触发

保留collection.completed的原有发现/入库语义。视频类monitor在ready后用实际转写与画面文本重新评估命中，再触发整理工作流。窗口内按document_id和revision去重；多个长任务陆续完成时聚合有界批次，避免每个回调引起重复全量研判。[S08]

7 详细功能需求

下列需求编号同时出现在开发任务表和验收用例中。P0与P1共同构成完整首版范围。配置、接口、表名和事件中标为新增的内容是本项目设计要求，不代表当前仓库已经实现。

R01 行业知识域配置 P0

在 workspace 内配置领域名称、问题范围、术语及同义词、包含与排除主题、来源规则、知识类型、复核人、处理预算和保留策略。所有运行冻结 profile 版本。

验收要求：同一视频按两个领域运行得到独立归类与可追溯的 profile_version，修改配置不改变历史结果。 [S01][S06]

R02 视频来源管理 P0

首版支持 B站和抖音的单视频链接及指定账号增量订阅；展示连接状态、最近成功时间、凭据引用、处理模式及失败原因。合集等扩展能力单独列出。

验收要求：两个平台分别完成一次手工提交和两轮账号增量发现；无凭据的受限资源显示需授权。 [S02][S10][S15]

R03 持续调度 P0

复用 Loom 的 interval 或 cron、时区和授权链。一次配置后后台运行，支持暂停、恢复、立即运行和有界补采。

验收要求：关闭聊天和浏览器后跨两个调度窗口仍执行；重启和错过窗口不导致重复发布或无界补跑。 [S02][S08]

R04 增量发现与游标 P0

按平台原生 ID 和分P识别视频；区分稳定watermark、分页checkpoint和处理进度。每页清单与任务原子保存；仅完成扫描至旧边界或穷尽结果时推进watermark。

验收要求：分页中断、重复页、页上限和乱序发布均保留partial与checkpoint；不能把未完整扫描当成已追平，重复条目不产生重复文档。 [S02][S15]

R05 统一异步任务 P0

手动、定时、MCP 三种入口进入同一宿主 operation 和 video_job；使用内容及处理版本指纹、租约、心跳和幂等映射。

验收要求：相同 scope、视频、内容版本和配置重放返回同一活动任务；同一幂等键不同参数返回冲突。 [S02][S03]

R06 媒体获取与下载 P0

通过 DTK 适配器获取平台元信息和媒体；支持字幕优先、音频、完整视频三种策略。对象进入宿主受控存储，记录哈希、时长、大小和来源。

验收要求：已授权视频可下载并校验哈希；短链归一化；禁止把临时下载链接当永久证据地址。 [S15][S16]

R07 字幕与语音转写 P0

优先保留可用时间轴字幕，缺失或低质量时调用宿主 ASR；记录语言、来源、分段起止时间、原始文本及术语修订。

验收要求：无字幕中文视频可生成时间轴文本；人工修订生成新版本；不伪造未返回的说话人或时间戳。 [S04][S05]

R08 长视频完整性 P0

按可配置时长与字节限制分段处理，保存完整性清单和断点；显式返回缺口、超限、取消和覆盖范围。

验收要求：超过原有 2000 segments 或长文本边界的样本不静默截断；缺失必需片段不能进入完整就绪态。 [S05]

R09 画面内容理解 P1

复用 BiliNote 抽帧思路与宿主 OCR，按场景变化抽帧并设置上限，必要时经宿主 Model Gateway 调用视觉模型。区分画面观察与模型推断。

验收要求：PPT、图表、工序演示和静音样本可返回带帧时间的证据；未分析区间和抽样策略可见。 [S04][S13][S14]

R10 来源修订与处理血缘 P0

保留 source revision、媒体哈希、字幕版本、处理器配置与派生文档关系；源标题更新不得覆盖已有转写。

验收要求：元信息重复采集后转写仍可检索；同媒体新模型产生派生新版本，旧引用仍可解析。 [S02]

R11 可追溯证据 P0

在现有 evidence_id 和 revision 语义上补充毫秒区间、帧引用及 UTF-16 文本映射；来源 URL 和源文件分开保存。

验收要求：点击知识卡引用可定位原文和视频区间；中文、emoji、跨段引用及旧版本均正确。 [S02][S05]

R12 知识就绪屏障 P0

仅由 Loom 在受信导入、必需处理阶段完成、文档修订与证据映射可读、文本索引可用之后发出 video.knowledge_ready。

验收要求：元信息 collection.completed 不触发最终知识整理；重投 ready 事件只产生一次有效下游运行。 [S02][S07][S08]

R13 结构化行业知识 P0

将材料整理为概念、事实、步骤、案例、参数、约束及风险等知识卡。每条包含适用条件、来源证据、事实或推断标记和复核状态。

验收要求：无证据的事实不能发布；数值保留单位和条件；信息不足时输出缺失项，不补写答案。 [S06][S07]

R14 相似知识与冲突 P1

识别重复内容、转载关系、同源断言与冲突观点；合并知识关系时保留每条证据和适用时间，避免把转载计为独立佐证。

验收要求：两个相互矛盾参数保留冲突及上下文；相同原始内容的跨平台转发不增加独立来源计数。 [S02][S06]

R15 知识复核与发布 P0

候选知识经过复核形成approved版本，再由发布命令转为published；修改使旧批准失效。记录复核者、理由和版本，支持撤回、失效、替代及回滚。

验收要求：发布需要证据完整、有效批准和发布权限。普通行业知识工具默认仅使用有效published知识；研究工具按权限读取ready材料，不能无声回退未审核知识。 [S01][S06]

R16 宿主 Agent 复用 P0

通过现有文档检索、读取、证据解析和行业工作流消费知识；增加状态与领域过滤，复用现有全文检索及可选向量能力。

验收要求：Agent 能回答来源视频特有问题并引用相应 revision 与时间段；跨 workspace 检索零泄漏。 [S01][S02][S07]

R17 视频 MCP 接口 P0

提供有界发现、短提交、任务状态、结果清单读取、取消能力；数据正文分页，大文件通过受控对象引用传递。

验收要求：调用在宿主超时预算内返回 task handle；MCP 结果本身不伪称已进入知识库。 [S03][S07][S17]

R18 原生行业整理 Skill P0

新增 Flow 行业 Skill，规定问题范围、筛选、证据核验、知识提取、冲突处理及输出 Schema；运行固定版本和工具权限。

验收要求：在宿主实际 intelligence 和 Canvas 执行路径验证加载；不依赖普通 SKILL.md 执行脚本。 [S06][S11][S12]

R19 Skill 候选与版本发布 P1

经复核的方法论可生成 Skill 候选，冻结证据与基线，进行业务用例回归后批准，生成源控发布包并按现有构建部署安装流程生效。

验收要求：新旧版本可比较、评测和回滚；批准、部署、安装状态分离；普通新视频不自动改生产 Skill。 [S06][S12]

R20 宿主内嵌界面 P0

在原工作区增加视频源、任务进度、知识候选与证据查看入口，延用身份和交互；完整首版增加视觉证据与 Skill 发布视图。

验收要求：用户可在宿主完成配置、运行、定位失败、复核和引用，无需登录另一套笔记应用。 [S01][S07][S08]

R21 权限与受信上下文 P0

tenant、workspace、actor、grant、source scope 来自服务身份和宿主授权上下文，不接受模型自报权限。执行和发布时重检授权。

验收要求：篡改任务ID、scope、对象路径或过期授权均失败；撤销来源后不再推进发布。 [S01][S03][S09]

R22 连接及内容隔离 P0

内网 MCP 采用显式服务白名单与独立传输策略；视频文字只作为材料。控制重定向、域名解析、日志秘密和不可信文件类型。

验收要求：不能借视频链接访问元数据或任意私网；注入型字幕不会改变系统指令或执行未批准工具。 [S03][S09]

R23 失败恢复与取消 P0

错误按需授权、限流、临时故障、永久不可用、预算不足及外部结果不明分类。先核对外部任务再决定重试；取消同时记录宿主阻止发布与远端停止状态。

验收要求：Worker重启复用已确认外部任务；结果不明时暂停盲目重提；旧租约不得提交，取消后晚回调不能恢复成功；已发生usage保留。 [S02][S16]

R24 运行观察与资源预算 P0

展示每阶段耗时、队列、失败分类、处理媒体分钟数、模型 usage、存储量及估算成本；复用宿主预算记账和审计能力。

验收要求：可从 operation 追到外部任务和模型调用；触发额度后阻止新重任务并保留待办。 [S01][S02][S03]

R25 保留删除与失效 P0

分别处理停用订阅、媒体正常到期、远程下架、撤权和内容擦除。保存期与可用权限独立判断；撤权/擦除传播到索引、知识、缓存和Skill依赖。

验收要求：媒体到期显示不可播放但保留仍获授权的文本证据；撤权/擦除后禁止再检索或发布受影响内容；恢复备份不复活撤回数据。 [S01][S02]

R26 依赖与部署 P0

锁定三个项目的版本，保留修改记录和上游许可证通知；独立部署 DTK 及视频执行组件，业务权威仍在宿主。

验收要求：可在干净环境启动并完成冒烟；升级适配器通过固定契约样本，不自动追随上游 main。 [S01][S13][S15]

R27 质量评测与回归 P0

建立可使用的视频、证据标注和业务问答集，覆盖双平台、长视频、噪声、静音视觉、来源更新与错误场景；比较原宿主基线。

验收要求：验收报告能追溯到数据版本、模型、配置及判定者；未经真实端到端通过的项不能标为上线完成。 [S18]

R28 灰度与回滚 P0

增量迁移、feature flag、单工作区灰度、数据备份及恢复演练；可暂停新视频任务并保留已导入文档和历史证据。

验收要求：关闭功能不破坏现有 RSS Telegram WeChat；任务及索引回滚按版本完成，不直接删除共享表。 [S01][S02][S10]

R29 受控运维 CLI P2

可选提供基于宿主 API 的 source、job、replay、export 命令；复用鉴权和幂等，不把上游直连数据库 CLI 暴露给 Agent。

验收要求：相同操作的 CLI 与宿主界面结果一致；只读或受限凭据无法执行越权重放。 [S01][S15]

R30 扩展来源与高级管理 P2

在同一 Provider 接口上扩展 TikTok、合集及更多平台；按实际需求考虑动态 Skill registry 和更大规模检索。

验收要求：新增平台通过相同契约、权限、完整性及证据测试，无须改动核心知识模型。 [S06][S15]

幂等与指纹

采集身份建议采用workspace、platform、native_id、part_id。处理指纹包含media_hash或受信源版本、processor_version、profile_version、处理模态及关键模型/提示配置。相同指纹复用既有结果；需要重处理时生成新处理版本，保留此前引用。

原始和派生内容

平台标题、描述和字幕原件属于source revision。ASR转录与帧OCR是带处理provenance的材料表示；LLM摘要、视觉推断与知识卡是派生结论。通过parent与processor指纹关联，禁止用生成结论冒充作者原话或在下轮作为自身来源证据。视觉观察必须保留类型和帧原件。

不得把采集回来的简短描述覆盖已融合转写的正文。知识复核文本与自动重处理产物分别保留。文字证据offset必须对应宿主约定的title加两次换行再加body的UTF-16坐标，而非仅转写子串的局部坐标；旧revision引用保持不变。

知识卡字段

最小知识卡包含：knowledge_id、知识类型、标题、领域标签、问题或结论、适用对象与条件、步骤或参数及单位、反例与边界、来源证据、事实/观察/推断类别、有效时间、冲突关系、审核状态及版本。来源可信度、转写质量、证据完整性分别记录，不以一个模型置信分数替代事实校验。

返回与错误规范

统一返回schema_version、request_id、data或error。error包含稳定code、retryable、retry_after、stage、安全message和correlation_id。错误码覆盖AUTH_REQUIRED、RATE_LIMITED、SOURCE_UNAVAILABLE、LIMIT_EXCEEDED、BUDGET_EXCEEDED、INCOMPLETE_ARTIFACT、SCOPE_DENIED、IDEMPOTENCY_CONFLICT、EXTERNAL_OUTCOME_UNKNOWN和PROCESSOR_FAILED。MCP TextContent仅写短说明，避免与StructuredContent重复整份JSON导致超出宿主rune上限。

产物清单示例

第一阶段artifact_stage=input_ready，input_kind=platform_subtitles或media。只有字幕时media_sha256=null、availability=not_acquired，input_hash取自真实字幕或源payload，不承诺本地视频可播放。第一阶段只接收输入并启动处理，不触发knowledge_ready。

第二阶段artifact_stage=processing_complete，携带parent_manifest_sha256绑定已接收输入；包括transcript.parts的对象key、sha256、segment_count、start_ms、end_ms，以及coverage.required、completed、missing和processor版本。两阶段绑定同一video_job，但各阶段使用自己的attempt与fencing token，不复用已过期下载租约。

10 视频处理和知识整理规则

字幕与长音频

保留字幕原文件、原语言和原始时间轴；字幕质量不足时按配置回退ASR。长音频先检测长度、编码和有效语音区间，再按有重叠的可控片段处理并去重衔接。每片段独立保存状态与hash。静音不应被误计成转写缺失，有效语音覆盖与全视频覆盖分开表示。

时轴精度优先来自字幕或ASR段；人工修订语义不自动改变时间坐标。若修订导致逐字对应失效，降级为段级引用并显示alignment_method。译文另存，不拿译文偏移替代原文偏移。

视觉

根据处理策略抽取场景变化帧并以时间网格补充，合并相似帧。OCR记录文字、帧时间、位置及质量；VLM只对有价值且符合预算的帧分析。图表数字必须保留图表证据与单位，不能根据不清晰截图补全。每个任务使用独立临时目录，避免BiliNote原共享帧目录造成并发污染。[S14]

行业整理

整理Skill首先判断领域相关性，再提取可证实的最小知识单元。每一事实附证据，每一方法附前提、步骤、输出检查和失败条件。把视频作者主张与已经核验的结论分开；缺少额外佐证时保留“来源主张”类别。

关联相似知识时同时考虑实体、时间、参数单位和使用条件；差异可能来自版本或场景，不直接取多数票。重复转载共享origin_cluster，不因平台不同就认定独立来源。

发布与失效

P0默认候选需人工复核批准后发布。原始材料可供有权限研究和提炼Agent查阅，但保留来源主张或未审核标识。证据撤权或擦除后，撤销相关检索、播放和发布资格，失效缓存并阻断依赖Skill继续把它作为有效依据；历史修订显示withdrawn，不静默换成另一条来源。

停用订阅只停止未来发现；正常媒体到期只标记media_expired并停止承诺播放，仍获授权保留的转录证据可继续使用；远程下架标记remote_unavailable，再按保留授权处理。上述情况均不自动等同于用户擦除。

11 行业Skill的形成和发布

行业知识与Skill采用不同更新频率。新视频通常增加事实、案例或边界知识；只有稳定、可复用并在多个实际任务中有效的方法改变，才创建Skill候选。

内容	Skill中应包含	持续知识库中应保留

完整首版的原生发布链

候选创建后记录基础Skill版本、候选hash、支持与反对证据、适用行业范围、依赖工具及评测输入版本。评测固定模型配置，对比原版本及不启用候选的结果。行业人员批准后生成源控发布包，进入既有CI与部署；运行环境部署成功后才允许workspace安装并pin该版本。[S06][S12]

发布门禁包括Schema正确、每个规则可追溯、关键用例不退化、缺证与越界问题处理正确、工具权限无扩大。回滚更换workspace pin并保留历史运行引用，不覆盖旧包。动态热发布registry留到P2，完整V1不依赖它。

普通文件包

如提供SKILL.md辅助包，其职责是介绍如何调用已批准的视频MCP和检索工具。安装包不会自动部署服务、创建调度或运行shell脚本。必须在实际宿主Agent模式验证工具可用，避免把Canvas文件读取能力误当成所有intelligence模式共有能力。[S11]

14 安全 保留和运行维护

使用宿主工作区身份和服务主体，凭据仅以secret reference关联来源；平台Cookie和API key不得出现在模型输入、普通日志和MCP结果中。内部调用使用明确audience与有效期，受控对象key必须匹配scope和media类型。[S01][S03]

现有媒体key校验偏向Telegram路径，需要在API、worker、存储和读取策略中一致支持video路径；不能仅取消校验。对上传或下载内容检查大小、文件魔数和格式，处理任务隔离临时目录与资源上限。

来源配置记录使用依据、允许用途和有效期。应用不承诺能够获取任何受限视频；遇到登录、付费、DRM或无法访问的资源时明确阻断，并允许来源维护人提供合法可用原件。上游软件许可证和内容使用权限分别处理，保留BiliNote和DTK来源与依赖清单。

默认建议原媒体保存30天，失败临时产物7天；具体期限由工作区策略和使用依据决定。知识与原件的保留独立设置。删除采用先撤销访问和检索、再异步物理清理，保留不含原始内容的审计墓碑；备份恢复后重放删除标记。

运行告警与处置

对连接连续失败、待处理时间、处理缺口、死信积压、预算阻断和复核队列积压建立告警。告警通过宿主既有通知体系配置，不另建消息平台。运维手册覆盖刷新凭据、重跑失败阶段、回收失联任务、撤回错误知识、回滚Skill及升级平台适配器。
